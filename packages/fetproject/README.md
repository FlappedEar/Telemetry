# fetproject

The shared FlappedEar `.fetproject` document format, as a pure Dart package
with no Flutter dependency. FlappedEar Overlays reads and writes the same
format (KAN-170), so everything here must stay byte-compatible with it.

So far the package holds the document's content ids (FET-12). Reading and
writing documents follows in FET-7.

## Content ids

Overlays stores four SHA-256 ids in documents. Each is computed over Qt's
`QJsonDocument::toJson(QJsonDocument::Compact)` bytes of a basis object:

| Id | Basis | Dart |
| --- | --- | --- |
| `gates-v1:<hex>` | the ordered gates as `["start"\|"split", latA, lonA, latB, lonB]`, east-positive | `gatesV1Revision` |
| `compatibility-v1:<hex>` | `{version: 1, layoutId, direction, gateRevision}` | `compatibilityV1Id` |
| `track-segments-v1:<hex>` | `{version: "track-segment-v2", segments}` | `trackSegmentsV1Revision` |
| `<hex>` (lap derivation key) | `{version: "lap-derivation-v1", runId, sourceId, sourceFingerprint, trackConfiguration}` | `lapDerivationV1Key` |

A lap reference is matched by its compact JSON (`lapReferenceKey`).

## Qt's compact JSON

`qtCompactJson` and `qtJsonDecode` follow Qt 6.8.3. The rules that differ from
`dart:convert`:

- **Numbers are integers or doubles.** The parser stores any integral number
  that fits in int64 as an integer, so `1.0`, `1e0` and `1` are all written
  `1`. A double built in code is stored as an integer only up to 2^53 in
  magnitude.
- **Doubles** use the shortest digits that round-trip, in decimal or exponent
  form, whichever is shorter; the exponent has a sign and at least two digits
  (`1e-07`, `1e+21`). Negative zero is `0`; NaN and infinity are `null`.
- **Keys** are sorted by Unicode code point (`"\u{1F3C1}"` sorts after
  `"￿"`).
- **Strings** escape only `"`, `\` and characters below U+0020 (`\b \f \n \r
  \t`, otherwise `\u00xx`). `/`, U+007F and U+2028 are written as they are. A
  lone surrogate is written as a lowercase `\udxxx` escape.

## Evidence

`test/fixtures/qt_hash_vectors.json` is generated by a small Qt program that
calls Overlays' own functions (`timingGateRevision`, `lapCompatibilityGroupId`,
`trackSegmentSetRevision`, `EventProjectCodec::lapDerivationKey`,
`lapReferenceKey`), built from `arekkozuch/VBOOverlay` at `0ec7416` with Qt
6.8.3 on Linux. It holds 20 parser round trips, 1,333 doubles (fixed edge cases
and seeded random values), 48 gate sets, 15 track configurations, 23 segment
sets, 3 runs and 2 lap references. The tests check every vector byte for byte.

The generator is not part of this repository (no shared code). Its source is in
the project files under `fet-goldens/hash-vectors/`; it is seeded, so a rerun
gives the same file (SHA-256 `6f3c77ed…6e65`).

## Behaviour carried over as found

These are Overlays' current behaviour, matched rather than fixed (owner
decision "copy", 2 October 2026):

- The gate-revision check is the regular expression `^gates-v1:[0-9a-f]{64}$`
  in Qt (PCRE2), where `$` also matches before a final newline. A revision
  followed by `\n` therefore counts as known and is hashed with the newline.
- A layout name is known when `QString::trimmed()` leaves something, it has at
  most 128 UTF-16 code units and no NUL. Qt's whitespace set (25 characters,
  listed in the vectors) is used, not Dart's `trim()`.
