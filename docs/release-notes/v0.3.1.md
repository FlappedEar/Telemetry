## FlappedEar Telemetry 0.3.1 (pre-release)

This release is the fixes from the latest audit: units in analysis, saving, profile import, the Windows installer and the way releases are signed. It installs over 0.3.0 and earlier releases, and over Android builds from `main` made before this change, and keeps your saved days. A `main` build made after it is signed with another key: save your days elsewhere before installing a release over it. From 0.2.6 on, **Settings › Check for updates** finds this release.

### Units in analysis

- The same drive now gives the same results (apart from rounding) whether it was recorded in g or m/s², in °C, °F or K, and in km/h, mph or m/s. Before, a VBO that declared its acceleration in m/s² only in its header was read as g (G-G and where braking starts), Fahrenheit and Kelvin temperatures were filtered with Celsius limits, and mph recordings gave a unit mismatch in coasting.
- A unit the app cannot read now gives a stated reason and no value, instead of being read as the default.
- The G-G note that units are not declared no longer appears on VBOs that declare their acceleration units in the header. The Corner Analyzer shows deceleration in g (m/s² recordings are converted), and charts and map layers label values in the units the recording declares and apply their plausibility limits in that unit.

### Saving and the driver profile

- If a circuit name cannot be saved on the device, the **Name this circuit…** dialog now says so and stays open so you can try again. If forgetting a name cannot be saved, a message says the name comes back when the app is closed. If a fetched circuit list cannot be saved, it is used until the app is closed and fetched again at the next start.
- The driver profile is now measured from the day as it was saved. An edit made while a save was running, or a save that failed, no longer moves the profile ahead of the day on disk.
- A profile bundle is refused whole, and your profile left untouched, when a day in it differs only by letter case from another day in it or in your profile (they would overwrite each other on Windows and macOS).
- A bundle is also refused when it is over 16 GiB, when any recording in it is over 128 MiB (the importers cannot open those anyway), or when it holds more than 10,000 days or 20,000 recordings. An export leaves out, and lists as missing, a recording over 128 MiB, and says so when the profile is more than one bundle can hold.
- A file with absurdly deep nesting now gives the usual import error instead of crashing the app.
- On Android, copies of recordings made while importing that no saved day and no unsaved-day recovery uses are removed when the app starts, once they are more than a day old. If a day file or the recovery cannot be read, nothing is deleted. Deleting a day keeps the copies that another day or the unsaved-day recovery still uses.
- When you change a day quickly (exclude a lap, change the speed unit) or close it, the calculations that are no longer needed are stopped instead of running on in the background.

### Windows installer

- The installer now always installs into `%LOCALAPPDATA%\Programs\FlappedEar Telemetry` and ignores a different folder given on its command line (`/D=`), so it can no longer delete a folder of yours. It leaves alone an existing folder of that name that it did not create, and it stops while the app is running: close the app and run it again.
- An update copies the new files aside first, so if the copy fails the old version stays. Your saved days are not in the install folder and are never touched. The installer is still not signed.

### Releases and Android builds

- The Android release key is no longer kept where a pull request could reach it. A release is signed in a separate step that runs no Flutter, Gradle or pub code, and only after CI has passed on that exact commit. It is the same key as before, so this release installs over the earlier ones.
- Android builds from `main` and from pull requests are now signed with their own throwaway key, so they no longer install over a release. To keep your saved days, install releases only. The install page of the user guide says so.

### Install

Android: the `.apk` below. macOS 12 or later: the `-macos.zip` below; it is not notarized; the install page says how to open it the first time. Windows 10 or 11: the `-windows-setup.exe` (or the `-windows.zip`) below; not signed. Check downloads against `SHA256SUMS.txt`.
